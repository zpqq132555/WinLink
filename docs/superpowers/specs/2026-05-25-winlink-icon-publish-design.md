# WinLink 图标接入与文件夹版发布设计

## 背景

当前 `WinLink.App` 是一个基于 `net8.0-windows` 的 WPF 桌面应用。项目已经具备基本功能和测试，但还没有正式的应用图标，也没有将图标纳入可执行文件与窗口显示链路。本次目标是在不引入安装器的前提下，为应用补齐统一图标，并完成一轮可分发的文件夹版发布。

## 目标

- 为 `WinLink.App.exe` 提供正式的应用图标。
- 为主窗口和相关对话框提供统一的窗口图标。
- 生成一份可直接分发的文件夹版发布产物。
- 保持本次改动只覆盖图标资源接入和发布链路，不改动无关业务逻辑。

## 非目标

- 不引入 `MSI`、`MSIX` 或其他安装包方案。
- 不新增托盘图标、通知区图标或文件类型图标。
- 不调整现有界面布局、配色或交互流程。
- 不对发布流程做额外平台扩展，例如单文件 `exe`、自包含发布或自动升级。

## 设计约束与假设

- 目标平台为 Windows，发布方式使用 `dotnet publish` 的文件夹版输出。
- 当前项目没有现成品牌素材，因此本次图标需要在项目内新增可维护资源。
- 图标需要兼顾 `16x16` 到 `256x256` 多尺寸显示场景，优先保证任务栏、窗口标题栏和资源管理器中的清晰度。
- Windows 资源管理器可能受图标缓存影响，验证时以新生成发布目录中的实际显示结果为准，必要时通过新目录重新验证。

## 方案比较

### 方案 A：纯几何矢量图标转 `.ico`

使用简单、对称、可缩放的几何链环图形作为源图，再导出为多尺寸 `.ico`。

优点：

- 小尺寸下更容易保持清晰。
- 接入 `ApplicationIcon` 和 WPF `Icon` 的兼容性最好。
- 资源维护成本低，后续替换也简单。

缺点：

- 视觉表现偏工具化，质感会克制一些。

### 方案 B：AI 位图图标直接转 `.ico`

先生成带质感的位图，再直接写入 `.ico`。

优点：

- 容易获得更强的视觉表现。

缺点：

- 小尺寸下容易模糊。
- 后续要继续维护和修订时成本更高。

### 方案 C：字母与链环混合品牌图标

将 `W` 或 `WL` 与链环结构混合设计，作为更品牌化的图标。

优点：

- 品牌识别更强，适合长期演进。

缺点：

- 设计复杂度高。
- 小尺寸下更容易失真，需要更多迭代。

## 选定方案

本次采用方案 A：纯几何矢量图标转 `.ico`。

理由：

- 当前目标是尽快补齐“应用图标 + 窗口图标 + 文件夹版发布”这一整条基础链路。
- 该方案风险最低，最适合桌面程序小尺寸图标场景。
- 后续如果需要更强品牌感，可以在不改变接入方式的前提下替换资源文件。

## 图标视觉设计

### 图形语义

- 主图形使用两个错位链环，表达“链接”和“连接管理”。
- 链环之间加入一个连接节点，强调“建立关系”和“链接操作”。
- 图形整体采用圆角几何风格，避免过于生硬的系统图标观感。

### 配色方向

- 主色使用偏 Windows 工具气质的蓝青色系。
- 背景保持浅色或透明，保证在资源管理器与标题栏环境中都有足够对比。
- 边缘与主体对比要足够高，避免 `16x16` 尺寸下融成一团。

### 输出要求

- 最终生成一份 `.ico` 文件。
- `.ico` 中至少包含 `16x16`、`32x32`、`48x48`、`64x64`、`128x128`、`256x256` 尺寸。
- 项目内保留一份源图文件，便于后续继续迭代。

## 项目接入设计

### 资源组织

在 `src/WinLink.App` 下新增图标资源目录，统一存放源图和最终 `.ico` 文件。资源路径固定在项目内，避免发布或构建时依赖外部路径。

建议结构：

```text
src/WinLink.App/Assets/Icons/
  WinLinkIcon.source.svg
  WinLinkIcon.ico
```

如果实际生成工具更适合使用 `png` 作为中间文件，可以在同目录保留必要中间产物，但以最少资源为原则，不额外保存无用导出文件。

### 可执行文件图标

在 `src/WinLink.App/WinLink.App.csproj` 中设置 `ApplicationIcon` 指向新增的 `.ico` 文件。

这样可以保证：

- 构建后的 `WinLink.App.exe` 持有正式程序图标。
- 文件夹版发布产物中的主程序在资源管理器中显示自定义图标。

### 窗口图标

在主窗口和需要显示应用身份的对话框上设置统一 `Icon` 属性，指向同一份项目内图标资源。

接入范围：

- `MainWindow.xaml`
- `AboutWindow.xaml`
- 其他当前由应用主动打开、且需要显示窗口图标的一致性窗口

原则：

- 统一使用同一资源，避免不同窗口图标不一致。
- 只补图标，不改动现有窗口布局和逻辑。

## 发布设计

### 发布方式

本次使用 `dotnet publish` 生成文件夹版发布目录。

该方式的特点：

- 不新增安装器依赖。
- 输出稳定，便于验证图标是否被正确写入主程序。
- 适合当前“先跑通发布链路”的目标。

### 发布结果预期

发布成功后，应得到一个可直接分发的目录，至少包含：

- `WinLink.App.exe`
- 应用运行所需的依赖文件

用户在该目录中直接双击主程序即可运行，并看到统一的新图标。

## 验证策略

### 自动验证

1. 构建验证
   - 执行项目构建，确认编译通过。
2. 发布验证
   - 执行 `dotnet publish`，确认输出目录生成成功。
   - 确认发布目录中存在 `WinLink.App.exe`。

### 手工验证

1. 运行源项目或发布产物，确认主窗口标题栏显示新图标。
2. 确认任务栏中的应用图标与窗口图标一致。
3. 打开资源管理器，确认发布目录中的 `WinLink.App.exe` 显示新图标，而不是默认图标。

### 失败处理

- 如果窗口图标生效而资源管理器仍显示旧图标，优先怀疑 Windows 图标缓存，而不是立即修改资源接入逻辑。
- 如果小尺寸显示不清晰，优先简化链环内部细节，再重新导出 `.ico`，不增加额外装饰元素。

## 实施步骤

1. 新增项目内图标源文件与最终 `.ico` 文件。
2. 在项目文件中接入 `ApplicationIcon`。
3. 在主窗口和相关对话框上接入统一 `Icon`。
4. 执行构建与文件夹版发布。
5. 验证窗口图标、任务栏图标与发布产物图标表现。

## 验收标准

- 项目编译通过。
- 文件夹版发布成功。
- 发布目录中存在 `WinLink.App.exe`。
- 主窗口和相关窗口显示统一的新图标。
- 资源管理器中发布产物主程序显示新图标。
- 本次改动不影响既有业务逻辑与测试基线。
