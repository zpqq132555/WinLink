## 背景

WinLink 当前只支持文件或目录链接的受管创建、刷新、重建与删除。对于“把一个目录真实复制到多个目标目录，并在源目录后续变化时再次同步”的场景，现有链接策略并不适合：目录链接会直接共享同一份内容，不能满足“目标上是实体目录”的诉求；而普通复制又缺少后续变更检测、统一同步和受管提示。

这次讨论收敛出的目标，是在现有“链接管理”之外新增一条“目录镜像同步”能力，继续复用 WinLink 的受管记录、状态检查、批量操作和结果反馈体系。

## 决策链

### Q1：目录镜像同步应该挂在现有链接策略下，还是作为独立能力存在？

- 结论：作为独立能力存在，不把它塞进 `SymbolicLink / Junction / HardLink` 体系。
- 原因：
  - 真实拷贝和链接不是同一类磁盘语义。
  - 现有“删除链接 / 重建链接 / 检查链接目标是否仍匹配”的行为，直接套到镜像目录上会语义错位。
  - 独立建模后，后续才能自然扩展“待同步”“目标有本地改动”“同步完成”等状态。

### Q2：镜像同步的语义是“增量复制”还是“真镜像”？

- 结论：采用真镜像。
- 定义：
  - 源目录新增的内容要复制到所有目标目录。
  - 源目录修改过的内容要覆盖到所有目标目录。
  - 源目录中已删除的内容，也要从目标目录中删除。
- 原因：
  - 用户明确希望是“目录镜像同步”，而不是“只补新增、不管删除”的宽松复制。
  - 真镜像的用户心智最简单，状态也最容易解释。

### Q3：如何识别“源目录变了，需要同步”？

- 结论：为每个受管镜像源保存一份上次成功同步时的目录快照摘要，再在启动或刷新时重新计算当前快照并比较。
- MVP 快照内容：
  - 相对路径
  - 文件大小
  - 最后写入时间
- 原因：
  - 只看目录时间戳太脆弱，容易漏判。
  - 直接做全文哈希虽然更稳，但第一版复杂度偏高。

### Q4：什么时候提示用户“源目录有变化，是否同步”？

- 结论：至少两处统一触发：
  - 打开应用后完成初次状态检查时
  - 用户手动刷新受管项状态时
- 补充：
  - 进入“已链接”页签时如果触发刷新，也应复用同一套检测结果和提示逻辑。
- 原因：
  - 用户已经明确要求“打开应用或刷新时发现源更变，提示是否同步”。
  - 不做后台 watcher，先用启动和刷新覆盖主要使用场景。

### Q5：如果目标目录被用户手工改过，是否直接覆盖？

- 结论：不静默覆盖，先提示确认。
- 处理方式：
  - 检测到目标目录自上次同步后发生本地改动时，将其标记为“目标有本地改动”或等价警告状态。
  - 用户发起同步前，明确提示继续同步会覆盖该目标上的改动，并清理掉源目录中不存在的额外内容。
- 原因：
  - 真镜像本身就有覆盖性；如果不提示，用户容易误以为只会补齐源目录新增内容。

### Q6：镜像目标的“断开 / 删除”应该怎么定义？

- 结论：对镜像目标执行删除动作时，直接删除目标目录实体，并把该目标标记为已断开。
- 保留：
  - “移除记录”仍然是只删除注册表项、不碰磁盘实体的独立动作。
- 原因：
  - 镜像目标本来就是一份受管复制物，删除它的预期就是删除那份实体目录。
  - 这也和现有“删除链接”和“移除记录”双动作的心智保持一致。

## 取舍

- 不把镜像模式扩展到文件源，第一版仅支持目录源。
- 不做实时文件系统监听，第一版只做启动/刷新检测。
- 不做文件级可视 diff 界面，第一版只做状态提示和同步前确认。
- 不做“只同步部分目标”的复杂批处理，第一版优先提供“同步到所有目标”。

## 已确认方案

新增一个“目录镜像同步”能力：

1. 在创建任务时，目录源可选择“链接模式”或“镜像模式”。
2. 镜像模式首次执行时，把源目录真实复制到一个或多个目标目录。
3. WinLink 为镜像源和每个目标记录上次同步基线。
4. 启动应用、进入受管页触发刷新或手动刷新时，系统比较当前源快照与已记录基线：
   - 若源变化，标记为待同步，并提示是否同步到所有目标。
   - 若目标也被本地改动，提示继续同步会覆盖改动。
5. 同步执行采用真镜像语义，并写入执行历史。
6. 删除镜像目标时，直接删除目标目录；移除记录仍保持只删登记不删磁盘。

## 待后续再考虑的问题

- 是否需要为大目录引入更强的快照算法或分阶段扫描提示。
- 是否需要支持“只同步某一个目标”或“跳过有本地改动的目标”。
- 是否需要在受管详情里展示更细的镜像状态文案，例如“待同步”“同步中”“目标有本地改动”“最近一次同步时间”。
