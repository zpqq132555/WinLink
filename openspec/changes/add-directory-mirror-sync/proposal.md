## Why

WinLink 目前擅长管理链接，但还不能管理“真实拷贝后再持续同步”的目录分发场景。用户已经有明确需求：源目录第一次应被真实复制到多个目标目录，后续源目录变化时，应用在启动或刷新时能发现变更并提示是否同步。现在如果继续靠目录链接或手工复制，一方面无法得到实体目录，另一方面也没有统一的变更检测、覆盖提示和受管历史，因此值得把“目录镜像同步”补成一等能力。

## What Changes

**目录目录分发方式**
- From: 目录源只能按链接策略创建受管目标。
- To: 目录源新增“镜像模式”，首次执行时将源目录真实复制到一个或多个目标目录。
- Reason: 满足“目标目录必须是实体目录”的场景。
- Impact: 非 breaking；影响目录源的新建与受管管理流程。

**后续变更检测与同步**
- From: WinLink 不会记录目录复制基线，也不会在启动或刷新时提示同步。
- To: WinLink 记录镜像源快照，在启动或刷新时检测源目录变化，并提示是否同步到所有目标目录。
- Reason: 让真实复制后的目录仍具备后续集中维护能力。
- Impact: 非 breaking；新增受管状态与同步动作。

**目标手工改动确认**
- From: 目录复制场景下没有“目标被手工改动”的受管提示。
- To: 如果目标目录自上次同步后被本地改动，系统在同步前必须提示继续操作会覆盖改动并清理多余内容。
- Reason: 真镜像具备覆盖性，需要把风险前置给用户。
- Impact: 非 breaking；新增同步前确认文案和状态提示。

## Capabilities

### New Capabilities
- `directory-mirror-sync`: 管理目录镜像模式的创建、变更检测、同步提示、目标覆盖确认和断开删除行为。

### Modified Capabilities
- None.

## Impact

- 受影响代码主要集中在 `src/WinLink.App` 的模型、执行服务、状态检查服务、主界面交互和受管列表动作。
- 需要补充目录快照与镜像同步相关测试，主要位于 `tests/WinLink.App.Tests`。
- 需要新增一份 capability spec，并让后续实现与执行历史、受管状态文案保持一致。
