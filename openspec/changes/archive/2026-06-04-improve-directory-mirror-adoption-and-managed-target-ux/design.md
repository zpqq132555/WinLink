## Context

WinLink 当前已经具备目录镜像、受管记录、预设直连应用和“已连接”页状态检查能力，但这些能力之间默认假设“目录镜像的首次复制一定由 WinLink 自己发起”。在 `opsx-init` 等先完成真实复制、再由 WinLink 接管的场景中，这个假设不成立，导致系统只能看到“目标已存在”，却无法把现有镜像结果登记为后续可同步的受管目标。与此同时，“已连接”页还存在两个交互问题：目标行选中会自动展开明细，而“查看详情”又承担部分详情展示；移除记录后刷新列表时，也没有保留当前选中上下文。

本次设计需要同时解决目录镜像的“采纳已有结果”能力，以及受管目标详情与选中恢复的稳定性。受影响的主要干系点包括目录镜像执行服务、预设预览/工作台轻校验、已连接页目标表和受管列表刷新逻辑。

## Goals / Non-Goals

**Goals:**
- 支持目录镜像在目标目录已存在且内容与源一致时，仅登记受管记录与同步基线。
- 让目录镜像的预览、校验、执行和历史记录对“可采纳已有镜像”使用一致语义。
- 让“已连接”页中“选中目标”和“查看详情”职责分离，不再选中即展开大块明细。
- 在移除单个目标记录后优先保留当前受管源任务和合理的当前目标。

**Non-Goals:**
- 不尝试自动判断 `opsx-init` 的来源或为某一入口做特例分支。
- 不为目录镜像引入新的后台同步机制或自动同步策略。
- 不持久化单个“查看详情”展开状态，也不改造现有 UI 状态文件结构去记录该状态。
- 不重构受管记录聚合模型或大幅改写目标表视觉结构。

## Decisions

### D1：把“采纳已有镜像”做成目录镜像模式的通用分支
- **选择**：在目录镜像模式下，若目标目录已存在且与源目录快照一致，系统把它识别为“可采纳”，允许用户确认后仅登记受管记录和同步基线。
- **理由**：用户问题虽然由 `opsx-init` 引出，但底层语义是“已有真实镜像结果尚未登记”，属于目录镜像本身的能力缺口。做成通用规则后，预设、普通任务、后续历史记录都能复用同一语义。
- **已考虑 alternative**：
  - 只给 `opsx-init` 做特例：会让系统出现一套通用逻辑和一套入口特例，后续难以维护。
  - 已存在且一致时自动采纳：虽然更省一步，但误收编现有目录的风险更高。

### D2：执行前显式确认采纳，而不是自动登记
- **选择**：计划阶段收集“可采纳已有镜像”的目标项，执行前给出统一确认；用户确认后才进入仅登记分支。
- **理由**：这能避免把本来就存在、只是恰好内容一致的目录误纳入 WinLink 管理；同时也让执行前提示与最终历史记录语义对齐。
- **已考虑 alternative**：
  - 发现一致后执行期静默登记：用户无法清楚感知系统是“采纳”而不是“新建”，也不利于解释行为变化。
  - 每个目标单独弹窗确认：实现简单，但会打断批量执行体验。

### D3：预设预览与工作台轻校验引入“可采纳”状态，而不是继续沿用布尔冲突
- **选择**：对目录镜像目标已存在的情况，新增“可采纳已有镜像”与“真实冲突”两类展示语义；目录镜像场景下不再把所有已存在目标统一标成冲突。
- **理由**：如果 UI 预览仍只显示“已冲突”，而执行期又允许采纳，用户会认为系统前后矛盾。预览、轻校验、执行计划必须使用同一套语义分层。
- **已考虑 alternative**：
  - 只改执行期，不改预览和轻校验：最小实现成本低，但用户在执行前仍会被错误提示误导。

### D4：移除 DataGrid 的“选中即展开”详情机制
- **选择**：去掉目标表 `RowDetailsVisibilityMode="VisibleWhenSelected"`，把 `StatusReason / 最近策略 / 最近同步 / 最近检查` 全部收进“查看详情”展开区。
- **理由**：选中行应该只用于表示当前操作对象，不应该隐式触发展开。让“查看详情”成为唯一详情入口后，交互模型更单一，也能避免用户在列表导航时不断触发大块布局变化。
- **已考虑 alternative**：
  - 保留 RowDetails，只调整 Expander 文案：仍然会保留双通道展开，问题本质不变。
  - 去掉 Expander，保留选中展开：与用户直觉冲突更大，不利于定位“原因”列的价值。

### D5：移除记录后按“优先保留当前上下文”恢复选中态
- **选择**：删除某个目标记录后，刷新列表时优先回到原受管源任务；如果该受管源任务仍有剩余目标，则选择剩余的相邻目标或首个目标；只有整条受管源任务消失时，才退回列表第一条。
- **理由**：用户正在处理的是“当前源任务下的某个目标”，删除单个目标后仍应停留在该任务上下文中。把焦点直接跳到第一条会打断连续操作。
- **已考虑 alternative**：
  - 始终回到第一条：实现简单，但体验最差。
  - 强制恢复到同一个目标 ID：目标已被删掉时没有落点，仍需要相邻回退策略。

## Risks / Trade-offs

- [Risk] 目标目录与源目录“快照一致”并不意味着它一定是用户想交给 WinLink 管理的镜像目录。 → Mitigation: 执行前显式提示“仅登记受管记录”，要求用户确认后才采纳。
- [Risk] 预设预览、轻校验、执行计划都要理解“可采纳”状态，若实现不一致会造成文案前后矛盾。 → Mitigation: 由同一套目录快照比较规则驱动，避免各层独立判断。
- [Trade-off] 引入“可采纳”后，执行计划不再只有降级确认一种确认项，执行前确认逻辑会稍复杂。 → 接受理由：这是为了换取目录镜像行为与 UI 预期的一致性，复杂度是可控且局部的。
- [Trade-off] 去掉 RowDetails 后，某些诊断信息需要多点一次“查看详情”才能看到。 → 接受理由：用户主动展开详情比被动选中触发布局变化更符合直觉，也更稳定。

## Open Questions

- 是否需要把“可采纳已有镜像”在执行历史中单独标识为一种成功类型，还是仅通过成功文案区分即可。
- “移除记录”后选择剩余目标时，是否采用严格的“原位置相邻优先”策略，还是简化为“优先第一项”即可；实现时可根据现有目标列表访问便利度决定。
