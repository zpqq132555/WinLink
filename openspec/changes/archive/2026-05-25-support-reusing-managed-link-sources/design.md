## Context

当前 WinLink 的受管源记录以“每次执行任务”为单位写入注册表与界面列表，因此同一个源如果分多次新增目标，会在 `已连接` 页里拆成多条记录。与此同时，`新建连接` 页把“源路径输入”和“目标编辑”当成一个完全手工的流程，虽然适合创建新源，但不适合给已经存在的受管源继续新增目标。

这次需求横跨 `ShellViewModel`、`MainWindow.xaml`、任务草稿模型、受管记录聚合逻辑和执行后的注册表合并逻辑，属于同一用户流程在展示层和执行层的联动调整，适合先固定设计再实现。

## Goals / Non-Goals

**Goals:**

- 让 `已连接` 页按“源名称 + 源路径 + 源类型”聚合展示同一受管源。
- 让 `新建连接` 页支持直接复用已连接源继续新增目标。
- 当任务复用已连接源时，锁定源路径和源类型，避免用户误改源定义。
- 执行后把新增目标并入已有受管源记录，而不是重复创建源记录。

**Non-Goals:**

- 不改变现有目标编辑方式、校验方式和批量执行入口。
- 不引入新的存储后端或新的外部依赖。
- 不处理“同名但不同路径”的自动合并，这类记录必须继续分开。

## Decisions

### 1. 在任务模型中显式记录“复用已连接源”状态

选择在 `LinkTaskDraft` 中新增可空字段，表示当前任务是否绑定了某个已连接源，而不是只靠 UI 状态判断。

原因：

- 这样可以把“源已锁定”和“执行时并入已有记录”的语义带到执行层。
- 后续切换任务、保存 UI 状态或补测试时不需要从控件状态反推。

备选方案：

- 仅在 ViewModel 中临时保存选择结果。优点是改动小；缺点是执行层看不到任务是否复用了已有源，后续容易出现 UI 和写库逻辑不一致。

### 2. `已连接` 页按源三元组聚合，但不直接改底层 JSON 结构

选择先在展示层与写入合并逻辑中使用“源名称 + 源路径 + 源类型”作为聚合键，而不是立刻迁移现有注册表 schema。

原因：

- 当前数据已经有 `ManagedLinkRecord` 和 `Targets` 结构，继续沿用即可满足需求。
- 这样不需要额外 migration，也不会影响已有归档和测试数据。

备选方案：

- 直接为注册表引入新的全局 source identity 规则并做数据迁移。优点是语义更强；缺点是这次需求不需要走到迁移级别，复杂度偏高。

### 3. 备注名控件改为“可输入 + 可选择已有源”的组合控件

选择把 `新建连接` 中的备注名输入改为 `ComboBox`，允许两种模式共存：

- 手工输入新备注名，按现有方式创建新源任务
- 选择已有受管源候选，任务进入“复用已连接源”模式

原因：

- 保留原有“新建全新源任务”的能力。
- 比新增单独的“复用已有源”入口更贴近当前工作台布局，学习成本更低。

备选方案：

- 新增独立按钮或单独区域专门选择已有源。优点是行为更显式；缺点是界面变重，而且会和当前备注名、源路径区域产生重复入口。

### 4. 同名不同路径的候选项使用显示文案消歧

选择在下拉候选中保留多条记录，并把显示文案渲染成 `名称 (路径)`。

原因：

- 用户明确要求同名不同路径要都列出。
- 这样不需要额外弹窗二次选择，仍然可以在一处完成决策。

备选方案：

- 名称去重或隐藏重名项。都会丢失真实可选项，不符合需求。

## Risks / Trade-offs

- [聚合键只基于三元组] → 如果后续需要支持“同源不同备注”的更复杂语义，还要再扩展规则；本次先严格遵循用户定义的合并条件。
- [UI 同时支持手工输入和下拉选择] → 需要处理好“从选择模式退回手工模式”的状态切换；通过显式字段和统一重置方法降低混乱。
- [执行后并入已有记录] → 如果写入时只按任务 `Id` 合并，会继续产生重复记录；需要把合并逻辑扩展到已连接源引用和三元组匹配。
