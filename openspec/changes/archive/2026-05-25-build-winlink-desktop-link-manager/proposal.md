## Why

WinLink 需要一个真正面向 Windows 用户的桌面工作流，用来创建和管理文件、文件夹链接，而不是继续依赖原始 `mklink` 命令、易错的命令行参数和不可控的手工清理方式。当前产品边界、页面结构和安全策略已经在探索阶段收敛稳定，适合正式固化为 OpenSpec change，作为后续实现的唯一基线。

## What Changes

- 新增 WinLink 首版桌面产品外壳，提供原生 Windows 主窗口、菜单栏以及 `新建链接`、`已链接`、`预设` 三个主标签页。
- 新增会话级链接任务工作台，支持一个源映射多个目标、同次会话暂存多条任务、编辑期轻量预检查、执行前完整校验以及尽力执行的批量创建流程。
- 新增受管链接注册表，使用 AppData 下的 JSON 文件持久化本工具创建或记录过的映射关系，并以此作为 `已链接` 页的唯一数据源。
- 新增严格模式的链接管理行为，包括状态刷新、重建链接、删除链接和移除记录，避免误删用户后来手工替换的真实文件或目录。
- 新增首版固定预设，覆盖 AGENTS 主配置分发和 skills 目录同步两个场景，支持变量路径、预览确认、冲突提示和转普通任务编辑。
- 新增执行结果摘要与轻量历史回看能力，帮助用户确认本次执行效果并定位失败原因。

## Capabilities

### New Capabilities
- `desktop-workspace-shell`: 定义 WinLink 的原生桌面主窗口、菜单栏、标签页布局和全局入口行为。
- `link-task-workbench`: 定义 `新建链接` 工作台中的任务编辑、校验、降级确认与批量执行行为。
- `managed-link-registry`: 定义受管链接记录、状态检查、严格删除、重建链接与移除记录行为。
- `preset-link-templates`: 定义首版固定预设、路径变量展开、预览确认以及转普通任务的行为。
- `execution-history`: 定义执行结果摘要与历史回看行为。

### Modified Capabilities
- None.

## Impact

- 在 `E:\project\nodejsProject\winlink` 下建立 WinLink 首版需求和设计基线。
- 为后续实现引入 AppData 下的 JSON 持久化模型以及 Windows 链接操作策略。
- 明确 WinLink 第一版只管理“本工具创建并记录”的链接，不做全盘自动发现。
- 为后续实现任务拆解、测试覆盖和 UI 结构落地提供规范边界。
